From "migrated" on paper to zero foreign tokens in seven files

Six product files counted as moved to the design system, yet still pulled old colours, spacing and components. A scripted, layer-by-layer audit found causes the Figma interface doesn't show, and turned "on the system" from a feeling into a number: zero.

Role
Design system owner: audit, mapping decisions, priorities, review
Tools
Figma, Plugin API scripts written with an AI assistant
Timeline
4 working days, Oct – Nov 2026; groundwork since April
Scale
Core library + 6 product files: back-offices, admin, flow builder, payment forms

How do you want to read the case?

Fixes in the design system weren't reaching the products, although the migration was "done". I made "on the system" measurable: a whitelist of sources and zero in the report. A layer-by-layer audit found two root causes — tokens with the same names but different values, and components that Figma had silently stopped publishing. I cleaned from the source to the consumers and classified exceptions instead of growing the scale. Four days later: zero foreign tokens in Core and six files, and a repeatable audit.

01 · The problem

Figma can't tell you how much a file is really on the system

  • 6 product files
  • Core
  • Fixes stuck in the library

Every fix to the design system was supposed to reach every product at once. It didn't: fixes stayed in the library and had to be chased file by file. Over six months every product had moved to Core, our design system. Screens were rebuilt and old libraries switched off. But the signs said otherwise:

  • Core itself showed an "updates available" banner from the old kit it should no longer depend on;
  • fixes in Core, like table cells, never reached the product files;
  • some elements stayed light in the dark theme;
  • spacing looked right but didn't switch with the scale.

A binding to an old library variable looks exactly like a binding to a new one. Some hide in instance overrides, text-run colours and slot content. Nobody can check thousands of layers by hand.

The goal: a measurable state of zero tokens, styles and components from outside the system — in Core and every product file, with no visual change to any screen.

02 · Approach

Define "ours", then audit layer by layer

  • Whitelist of sources
  • Passes by layer
  • Dry run first
  • A whitelist of sources. The colour collection, typography variables, the local spacing scale, text styles, Core effect styles and Core component keys. Everything else is a finding.
  • Passes by layer, not by file: instances and their main components, fill and stroke variables, text-run colours, text styles, effects, raw spacing and radii.
  • Source before consumers. Clean and publish Core first. In product files fix only what the file owns; anything inherited is fixed by publishing, not by hand in every file.
  • Dry run → decision → apply → re-audit. "Done" means zero in the report, not "looks fixed".

03 · Finding

Same names, different values

  • Paddings/1: 8 → 4
  • Map by value

The old and new spacing scales used the same names with a different step: "Paddings/1" was 8 in the old one and 4 in the new. Rebinding by name would have silently halved every gap.

Rejected

Map by name: fast, and every spacing in six product files changes size without anyone noticing.

Chosen

Map spacing by value, colours by name (their names and values matched). Values with no pair, like 0 or a 1 px stroke, are unbound and keep their number.

04 · Finding

The blocker nobody could see

  • ~1,500 bindings
  • 2 unpublished components

About 1,500 old bindings sat inside instances of just two components: the data list row and the table cell. Neither had been published for a long time. The reason was unused component properties left over from a refactor to slots. Figma marks such components invalid and drops them from publishing without a clear warning. A scan of all 182 components found 13 of these properties; removing them changed nothing visually and unblocked publishing.

Rule I took from it

If a library fix doesn't reach the files, first check whether the component publishes at all.

Publishing wasn't the end. "Update all" didn't relink files to the freshly published components: about 9,000 instances had to be swapped. The swap reset property values to defaults, so the script restored them — in one case a hidden "blacklisted" flag had become visible. Core also referenced itself: its own component was inserted by key, as a published copy of itself, which caused the update banner. New rule: inside the system, only local nodes.

05 · Decision

Explain exceptions instead of making them tokens

  • Intentional
  • Mistakes
  • Accepted as is

After binding everything that matched the scale, values like 10, 14, 6 and 2 were left. The easy way was to add them to the scale. I refused: the scale would swell to fit exceptions. Each case was classified instead:

  • Intentional: height geometry, like 14 + 20 + 14 = 48 for an input or 10 + 20 + 10 = 40 for pagination. Left raw.
  • Mistakes: a 9 px gap in a toast, 14.67 in a calendar. Moved to a scale step.
  • Accepted as is: payment-system logo colours, illustrations, Figma's service strokes. Not everything outside the system is an error.

06 · How AI was used

Scripts did the volume, review owned the result

  • Plugin API scripts
  • Decisions and review: mine

Every bulk change ran as a Plugin API script written with an AI assistant: scans, dry-run reports, rebinding, instance swaps. The decisions — what counts as ours, how to map, what to leave alone — and the review were mine. Changes to Core needed my explicit confirmation, never ran automatically.

Review mattered. The first pass reported clean colours, but Figma stores text-run colours in a separate field, and the script never looked there. Since then every pass ends with an independent re-scan.

07 · Honest part

What went wrong

  • First pass skipped text runs
  • "Update all" didn't relink
  • Payment forms

A clean first pass isn’t a clean file. Review owns the result.

Note to self
  • Trusting the first pass. It skipped text-run colours and looked clean. Only review caught it.
  • Assuming "update all" relinks. It didn't, and the swap that replaced it reset property values — one hidden flag went visible before the restore step was added.
  • Payment forms didn't fit the sweep. A pilot showed the old form component was functionally richer than the new one, so its migration became a separate project.

08 · Result

What changed after

  • 0 foreign tokens
  • ~9,000 instances relinked
  • No visual changes
Zero in Core and 6 files

No foreign variables, no broken instances, no deleted main components in the final run. The payment-form screens were left out and migrated as a separate project.

~9,000 instances relinked

Products use the current components again, so one publish in Core reaches every product.

No visual changes

No top-level frame changed size; spot checks found no differences.

Repeatable, not one-off

Dark theme and spacing switch as a whole; files have a build checklist and the audit is a reusable script.
